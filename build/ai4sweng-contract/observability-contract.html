AI4SWENG — Observability Integration Contract

Audience: All KIO Consortium Teams (KIO2–KIO13)  ·  Issuer: Central Platform Team (KIO1)  ·  Status: Normative

Welcome aboard. If you own one of KIO2 through KIO13, this is the whole agreement for getting your telemetry into AI4SWENG — and it is written to be followed, not filed away. The rule of the road is simple: you instrument your own code and push it to us. You never run a collector, you never expose a scrape or pull endpoint for us to poll, and you never talk to our PostgreSQL directly. Everything flows outward from your KIO in two independent streams, and we take it from there.

How your telemetry flows to us

Figure 1 — Two streams out of every KIO. ① OTLP/gRPC to our Collector (→ Prometheus + Tempo → Grafana); ② LLM traces straight to your Langfuse project. The Session Manager ties runs together by kio.id + session.id; KIOs never touch Postgres directly.
Figure 2 — Inside a single KIO: the SDK feeds one OTLP exporter (metrics + spans → Collector), while the Langfuse decorator sends the LLM call straight to your project. Every signal carries the five resource attributes.

The contract — two sections you agree to

§1 · NORMATIVEOnboarding & Connectivity

Getting connected is a five-minute job and one request to us. Here is the whole path from nothing to “we can see you.”

  1. Ask us for credentials. Open a request with the KIO1 platform team for your OTLP bearer token and your own Langfuse project keys. We issue both per KIO — and we never print them in a document like this one.
  2. Set the env vars (the block below the code): our Collector endpoint, the Authorization: Bearer header, the five resource attributes via OTEL_RESOURCE_ATTRIBUTES, and your LANGFUSE_* keys.
  3. Install the SDKs: opentelemetry-sdk, opentelemetry-exporter-otlp-proto-grpc, and langfuse.
  4. Attach the resource attributes to every signal — service.name, service.version, kio.id, deployment.environment (from the env) and session.id (stamped per run, on your traces).
  5. Verify — and this is the finish line. You are onboarded only once both land on our side: a test metric showing in Grafana and a test trace showing in your Langfuse project. One without the other doesn’t count.

§2 · NORMATIVETelemetry Compliance

Connected isn’t the same as compliant. Below is the floor every KIO holds to — six baseline metrics and the rules for your Langfuse traces.

Metric (dot-style)TypeLabelsWhat it tells us
kio.requestscounterkio.idRequests your KIO handled

Langfuse rule. Emit to your own Langfuse project — that’s how we keep isolation and billing per KIO — and stamp every trace with kio.id and session.id metadata, which is what lets us aggregate across all KIOs centrally. Keep it to one trace per session, with a span per LLM or tool call.

Two expectations. Export continuously, and emit a heartbeat (kio.heartbeat) so we can see your KIO is alive. Beyond the baseline, extra metrics are self-service — add whatever you need, as long as it follows the house rules below.

A real, working starting point

# --- env (ask the KIO1 platform team for the two secrets; never commit them) ---
# OTEL_EXPORTER_OTLP_ENDPOINT = https://collector.ai4sweng.internal:4317   # our Collector — gRPC + TLS
# OTEL_EXPORTER_OTLP_HEADERS  = Authorization=Bearer%20<YOUR_OTLP_TOKEN>
# OTEL_RESOURCE_ATTRIBUTES    = service.name=kio5,service.version=1.4.0,kio.id=kio5,deployment.environment=prod
# LANGFUSE_HOST / LANGFUSE_PUBLIC_KEY / LANGFUSE_SECRET_KEY               # your own Langfuse project keys

import time
from opentelemetry import metrics, trace
from opentelemetry.sdk.resources import Resource
from opentelemetry.sdk.metrics import MeterProvider
from opentelemetry.sdk.metrics.export import PeriodicExportingMetricReader
from opentelemetry.exporter.otlp.proto.grpc.metric_exporter import OTLPMetricExporter
from opentelemetry.sdk.trace import TracerProvider
from opentelemetry.sdk.trace.export import BatchSpanProcessor
from opentelemetry.exporter.otlp.proto.grpc.trace_exporter import OTLPSpanExporter
from langfuse import observe, get_client

KIO_ID = "kio5"
L = {"kio.id": KIO_ID}                              # every metric carries kio.id
res = Resource.create()                             # reads OTEL_RESOURCE_ATTRIBUTES (service.name/version, kio.id, environment)

# Stream 1 (metrics) -> Collector -> Prometheus
metrics.set_meter_provider(MeterProvider(resource=res,
    metric_readers=[PeriodicExportingMetricReader(OTLPMetricExporter(), export_interval_millis=5000)]))  # continuous export
m = metrics.get_meter(KIO_ID)
# Stream 1 (spans) -> Collector -> Tempo
tp = TracerProvider(resource=res); tp.add_span_processor(BatchSpanProcessor(OTLPSpanExporter()))
trace.set_tracer_provider(tp); tracer = trace.get_tracer(KIO_ID)

# the mandatory baseline -- each series labelled kio.id
requests  = m.create_counter("kio.requests")
latency   = m.create_histogram("kio.request.duration", unit="s")
errors    = m.create_counter("kio.errors")
tokens    = m.create_histogram("kio.llm.tokens", unit="{token}")
cost      = m.create_counter("kio.llm.cost")
heartbeat = m.create_counter("kio.heartbeat")       # continuous liveness

@observe()                                          # Stream 2: one Langfuse trace per session
def handle(request, *, session_id):
    get_client().update_current_trace(metadata={"kio.id": KIO_ID, "session.id": session_id})
    with tracer.start_as_current_span("kio.handle"):        # span on stream 1 -> Tempo
        requests.add(1, L)
        t0 = time.perf_counter()
        try:
            return answer(request)
        except Exception as e:
            errors.add(1, {**L, "error.type": type(e).__name__}); raise
        finally:
            latency.record(time.perf_counter() - t0, L)

@observe(as_type="generation")                      # a span per LLM call, on the same trace
def answer(request):
    reply = llm.chat(model="qwen2.5-coder:7b", prompt=request.text)   # your own LLM client
    ml = {**L, "model": reply.model}
    tokens.record(reply.in_tokens,  {**ml, "token.type": "input"})
    tokens.record(reply.out_tokens, {**ml, "token.type": "output"})
    cost.add(reply.cost_usd, ml)
    return reply.text

llm is your KIO’s own client (in AI4SWENG, shared.llm.factory.create_llm_provider()); reply exposes .text, .model, .in_tokens, .out_tokens, .cost_usd.

House rules (the conventions everyone follows)

  • Dot-style, stable names — kio.<domain>.<metric>. Once published, a name is a promise; renaming it is a breaking change.
  • Always include kio.id + session.id — kio.id on every metric and trace, session.id on every trace. These are how we correlate you back to the Session Manager.
  • No unbounded / high-cardinality label values — no raw request IDs, emails, or URLs in labels (session.id rides on traces, not metrics).
  • Never put secrets or PII in labels, span names, or Langfuse payloads.
  • Always set service.version — it’s how we tell one release from the next when something regresses.
  • New mandatory metrics come from us (added to this contract first); optional ones are yours to add, self-service, as long as they follow these rules.
