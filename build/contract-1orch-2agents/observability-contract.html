Architecture

Mandatory on every signal: service.name · service.version · agent.id · deployment.environment (OTel resource, from OTEL_RESOURCE_ATTRIBUTES) and session.id (minted by the orchestrator, on the owner’s trace). agent.id + session.id are the correlation keys — agent.id identifies the owner, session.id joins one run across owners.
No separate state store. This deployment has no Session Manager and no database. The orchestrator mints session.id and dispatches to the two owners; the key is resolved at query time — session.id lives on spans in Tempo and on traces in each Langfuse project. agent.id + session.id are the only correlation keys; nothing is persisted platform-side beyond the telemetry backends.

 

§1 · NORMATIVEOnboarding & Connectivity Requirements

Every item below is mandatory before an agent owner (repo-analyzer, bug-detector) is considered “onboarded”.

Platform side (we provide): the shared OTLP Collector endpoint (TLS), your per-owner OTLP bearer token and Langfuse project keys (issued out-of-band at onboarding — never printed in this contract), the Prometheus / Tempo / Grafana backends, and a session.id per run. Owner side (you do): steps 1–6 below.

  1. Credentials. Obtain the shared Collector’s OTLP bearer token (OTLP_BEARER_TOKEN — unauthenticated pushes are rejected with 401; presented via OTEL_EXPORTER_OTLP_HEADERS) and your own Langfuse project keys. TLS is deploy-time: the same env vars switch to https:// + the platform certificate — no code change.
  2. SDKs. Install opentelemetry-sdk, opentelemetry-exporter-otlp-proto-http, langfuse.
  3. Identity. service.name = agent.id = your owner id (repo-analyzer or bug-detector), plus service.version and deployment.environment. One owner = one identity across metrics, spans, and its Langfuse project.
  4. Instrument your run. We hand you a session.id per run; wrap your work in propagate_attributes(session_id=…, environment=…) and wrap the run root in @observe() (LLM calls in @observe(as_type="generation")) — one trace per session in your own project, every trace carrying agent.id + session.id.
  5. Isolate & flush. Init Langfuse with blocked_instrumentation_scopes=["<your-agent>.tracer"] so your stream-① OTel spans don’t duplicate into Langfuse; flush the Langfuse client and shutdown() the OTel providers before exit.
  6. Verification (definition of onboarded). Onboarded only when both appear on our side — e.g. for the bug-detector: agent.invocations{agent.id="bug-detector"} on Grafana/Prometheus and its run trace (generations + session.id) in the bug-detector Langfuse project.

§2 · NORMATIVETelemetry Compliance Requirements

Both owners MUST emit these — the baseline floor, each labelled agent.id:
Metric (dot-style)TypeLabelsMeaning
agent.invocationscounteragent.idTimes this owner was invoked (its request count)
agent.durationhistogramagent.idPer-invocation latency (seconds)
agent.errorscounteragent.id, error.typeInvocations that raised
gen_ai.client.token.usagehistogramagent.id, gen_ai.token.type, gen_ai.request.modelLLM tokens
llm.cost.usdcounteragent.id, gen_ai.request.modelEstimated LLM spend (USD)
On active sessions and run totals. The orchestrator receives the run and owns the session, so sessions.active — plus run-level runs.total / run.duration — is emitted by the orchestrator, not by repo-analyzer or bug-detector. Owners emit the per-invocation baseline above and never manage sessions.

Self-service extras (optional, per the guidelines): gen_ai.client.operation.duration, gen_ai.server.time_to_first_token, gen_ai.finish_reasons, and the bug-detector’s eval.bug_recall / eval.judge_quality (0..1).

Langfuse rules. Each owner emits to its own Langfuse project (repo-analyzer → its project, bug-detector → its project). One trace per session, per owner; spans per invocation/pass and per LLM call; generations carry model + token usage + cost + (gated) content. Every trace is stamped with agent.id + session.id. Eval scores attach to the owner’s trace via the Scores API, keyed by that project’s trace id.

Scope — batch vs. service. This deployment is a batch process (one run per invocation, then exits); metrics flush every 5 s and at exit. A long-running service deployment MUST additionally emit service.heartbeat (continuous liveness) — not emitted here because a run-once process has no meaningful liveness to report.

Reference implementation — real code (one agent owner)

# env (your agent owner)
#   OTEL_EXPORTER_OTLP_ENDPOINT = https://collector.us/        (we provide it; TLS)
#   OTEL_EXPORTER_OTLP_HEADERS  = Authorization=Bearer%20<OTLP_BEARER_TOKEN>
#   OTEL_RESOURCE_ATTRIBUTES    = service.name=<your-agent>,service.version=1.0.0,
#                                 agent.id=<your-agent>,deployment.environment=prod
#   LANGFUSE_HOST / LANGFUSE_PUBLIC_KEY / LANGFUSE_SECRET_KEY  (your own project keys)

import time
from opentelemetry import metrics, trace
from opentelemetry.sdk.metrics import MeterProvider
from opentelemetry.sdk.metrics.export import PeriodicExportingMetricReader
from opentelemetry.exporter.otlp.proto.http.metric_exporter import OTLPMetricExporter
from opentelemetry.sdk.trace import TracerProvider
from opentelemetry.sdk.trace.export import BatchSpanProcessor
from opentelemetry.exporter.otlp.proto.http.trace_exporter import OTLPSpanExporter
from opentelemetry.sdk.resources import Resource
from langfuse import Langfuse, observe, get_client, propagate_attributes
from your_app import provider                  # your existing LLM client: provider.chat(model, prompt) -> reply(.text, .in_tokens, .out_tokens)

AGENT_ID = "your-agent"                        # = service.name = agent.id
L = {"agent.id": AGENT_ID}                     # every metric carries agent.id
PRICE_IN, PRICE_OUT = 0.05 / 1e6, 0.20 / 1e6   # example: your model's USD per input / output token

# Stream 1 (metrics): your OTel metrics -> OTLP -> the Collector we provide.
# Resource.create() reads OTEL_RESOURCE_ATTRIBUTES (service.name/version, agent.id, environment).
metrics.set_meter_provider(MeterProvider(resource=Resource.create(),
    metric_readers=[PeriodicExportingMetricReader(OTLPMetricExporter(), export_interval_millis=5000)]))
m = metrics.get_meter(AGENT_ID)

# Stream 1 (spans): your OTel tracer -> OTLP -> Collector -> Tempo.
tp = TracerProvider(resource=Resource.create())
tp.add_span_processor(BatchSpanProcessor(OTLPSpanExporter()))
trace.set_tracer_provider(tp)
tracer = trace.get_tracer(f"{AGENT_ID}.tracer")   # this scope is the one blocked from Langfuse below

# the mandatory baseline -- one instrument each (every series labelled agent.id)
invocations = m.create_counter("agent.invocations")
duration    = m.create_histogram("agent.duration", unit="s")
errors      = m.create_counter("agent.errors")
tokens      = m.create_histogram("gen_ai.client.token.usage", unit="{token}")
cost        = m.create_counter("llm.cost.usd")

# Stream 2: your Langfuse client -> your own project (keeps stream-1 spans out of Langfuse).
Langfuse(blocked_instrumentation_scopes=[f"{AGENT_ID}.tracer"])

@observe(name="agent.run")                                   # one Langfuse trace per session (stream 2)
def run(task, *, session_id):                                # session_id is handed to you per run
    with propagate_attributes(session_id=session_id, environment="prod", metadata=L), \
         tracer.start_as_current_span("agent.run"):          # OTel span -> Tempo (stream 1)
        invocations.add(1, L)
        t0 = time.perf_counter()
        try:
            return call_llm(task, model="gpt-oss:20b")
        except Exception as e:
            errors.add(1, {**L, "error.type": type(e).__name__}); raise
        finally:
            duration.record(time.perf_counter() - t0, L)

@observe(name="llm.generate", as_type="generation")          # renders as a Langfuse generation
def call_llm(prompt, *, model):
    reply = provider.chat(model=model, prompt=prompt)         # your LLM call
    ml = {**L, "gen_ai.request.model": model}
    tokens.record(reply.in_tokens,  {**ml, "gen_ai.token.type": "input"})
    tokens.record(reply.out_tokens, {**ml, "gen_ai.token.type": "output"})
    cost.add(reply.in_tokens * PRICE_IN + reply.out_tokens * PRICE_OUT, ml)   # tokens x your price
    get_client().update_current_generation(                  # stream 2: tokens/cost -> Langfuse
        model=model, usage_details={"input": reply.in_tokens, "output": reply.out_tokens})
    return reply.text
A host that co-locates both owners in one process (like this reference) instead uses one explicit Langfuse(public_key=…) client per project; a standalone owner needs only the simpler @observe() form above.

Guidelines (conventions every owner MUST follow)

  • Dot-style, stable metric names — <domain>.<metric> (agent.duration, gen_ai.*, eval.*). Renames are breaking changes.
  • Always include agent.id + session.id — agent.id on every metric and trace, session.id on every trace. These are the correlation keys back to the orchestrator.
  • No unbounded / high-cardinality label values — no raw run ids, emails, or URLs in metric labels (session.id rides on traces, not on metrics).
  • Never put secrets or PII in labels, span names, or Langfuse payloads. Content capture is gated by OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT (set false for metadata-only).
  • Always set service.version — regressions are tracked across releases.
  • New mandatory metrics are announced by the platform (added to this contract first); optional metrics are self-service if they follow these conventions.
